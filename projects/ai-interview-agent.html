Project Overview

ARI (AI Recruitment Interviewer) is a production-inspired automated screening platform. In modern technical recruitment, reviewing hundreds of initial candidate profiles is a significant bottleneck. ARI resolves this by conducting conversational, interactive, voice-to-voice technical screening interviews, scoring answers in real-time, and compiling visual candidate reports for recruiters.

The platform uses a hybrid multi-model strategy: leveraging the OpenAI Realtime API for low-latency voice-to-voice streaming, and the Google Gemini API for structured assessment of transcripts against technical guidelines and expected answers. All data, from candidate responses to final summaries, is stored inside a highly structured PostgreSQL schema.

Module Explanations

1. Interview Orchestration

The ari-agent-chain package handles real-time audio chunking, WebSockets streaming, and the front-facing client conversation. It utilizes Chainlit for UI rendering and LangGraph to construct the conversation's state machine, feeding voice data chunks directly to the OpenAI Realtime WebSockets API.

2. Asynchronous Evaluation API

The ari-eval-api is an asynchronous REST microservice built with FastAPI. When a user finishes answering a question, their audio response transcript is pushed here. The service calls Google Gemini using structured prompts (containing the expected response guidelines) to evaluate answers on a 0-10 scale and output formatted JSON feedback.

3. Recruiter Dashboard

The ari-dashboard is a Streamlit dashboard tailored for HR managers. It pulls candidates' transcripts, raw answer recordings, and individual question scores directly from the PostgreSQL instance. It calls Gemini to generate a final executive summary report of the candidate, helping recruiters make data-driven hiring decisions.

4. Relational Storage Layer

Powered by PostgreSQL using SQLAlchemy ORM. It persists relational models for job roles, dynamic question pools, candidate identifiers, session timestamps, and highly granular evaluations (transcripts, raw grades, weighted scores, and specific LLM feedback).

Technical Highlights & Review

During local development, I focused heavily on ensuring robust error handling and testability:

- Mock Layer Integration: Set up dependency injection configurations allowing the ari-eval-api server to toggle between standard PostgreSQL database pools and a local mock_client.py based on environment flags, bypassing DB requirements during unit-test executions.
- Pydantic Guardrails: Outlined strict schemas enforcing JSON structure from Gemini calls (handling syntax, out-of-bounds scores, and validating field structures before SQL ingestion).
- Weighted Relevance Logic: Created custom SQL queries to multiply grades with relevance variables (relevance_weight), ensuring core skills (e.g. databases, concurrency) contribute properly to the total score.
