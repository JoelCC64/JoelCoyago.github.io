Project Overview

Executing heavy neural network models (like ResNet50 in TensorFlow) within HTTP request-response cycles can lead to high latency and thread blocking at the API layer. Under high load, this causes timeouts and gateway errors.

This project implements a distributed, microservices-based image classification infrastructure. By separating the system into decoupled containers, tasks are offloaded asynchronously. An API Gateway handles routing and client authentication. The gateway pushes incoming images to a Redis message queue. An independent TensorFlow worker then processes these jobs in the background, updating prediction results in a PostgreSQL database.

Service Explanations

Streamlit Dashboard UI

The client app provides login fields and image upload slots. It stores JWT credentials locally and renders classification tables along with historical feedback buttons.

FastAPI Gateway API

Serves the REST API. Validates requests via JWT, writes classification logs into PostgreSQL using SQLAlchemy, and enqueues classification tasks into Redis.

Redis Broker Broker

Maintains high-performance in-memory queues. It coordinates tasks between the FastAPI endpoints and TensorFlow model workers without blocking client requests.

TensorFlow Worker Worker

Monitors Redis queues. Downloads images from shared volumes, runs CNN ResNet50 inference, and commits final prediction lists back to PostgreSQL.

Stress Testing & Load Scaling

To verify performance under load, the platform was subjected to automated concurrency stress testing using Locust:

# Example Locust Run Command $ locust -f stress_test/locustfile.py --host=http://localhost:8000 --users=50 --spawn-rate=5

During test execution:
- Decoupled Architecture Resilience: The API Gateway maintained sub-10ms response times for JWT handshakes and metadata queries under 50 concurrent users.
- Queue Performance: Redis successfully queued classification requests during model execution spikes, shielding the client from server-side thread blocks.

Apple Silicon Optimization

A key contribution during deployment on Apple Silicon was resolving ARM64 compilation incompatibilities:
- Created a dedicated Dockerfile.M1 for compilation of TensorFlow and dependencies on M-series chips.
- Adjusted Docker Compose file mappings to dynamically load configurations depending on host architectures.
